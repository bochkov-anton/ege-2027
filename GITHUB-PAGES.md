# Публикация «Мой ЕГЭ» через GitHub Pages

**Режим:** один Android-планшет, GitHub хранит только статические файлы. Прогресс, ошибки, результаты и заметки — локально на планшете.

## Принцип работы

GitHub-репозиторий — код интерфейса, данные учебного плана, JS/CSS, иконки. GitHub Pages публикует эти файлы по HTTPS. Приложение на планшете один раз загружает их, кэширует для автономной работы, а личные данные сохраняет локально в localStorage. Ученице не нужен аккаунт GitHub.

**Репозиторий:** https://github.com/bochkov-anton/ege-2027

**Действующий адрес GitHub Pages:** https://bochkov-anton.github.io/ege-2027/ . После каждого обновления исходников дождитесь публикации и перезапустите PWA онлайн.

## Первичная публикация

1. Войдите в GitHub под своим аккаунтом. Создайте отдельный **публичный** репозиторий, например ege-2027. На бесплатном тарифе GitHub Pages работает с публичным репозиторием.
2. Загрузите на ветку main **содержимое** пакета ege-2027-android-pwa.zip, а не ZIP как один файл. В корне должны быть index.html, manifest.webmanifest, sw.js, JS и CSS. Иконки — в папке icons. Файл .nojekyll также должен лежать в корне.
3. В репозитории откройте Settings → Pages → Build and deployment → Source → Deploy from a branch. Выберите main и /(root), нажмите Save.
4. Дождитесь публикации, откройте ссылку HTTPS, проверьте экран «Сегодня».
5. На Android-планшете в Chrome откройте этот адрес и выберите в меню ⋮ → «Установить приложение» / «Установить и создать ярлык».
6. Проверьте без интернета: откройте несколько разделов онлайн, затем отключите Wi-Fi и убедитесь, что план доступен. Внешние PDF и видео требуют интернета.

## Публикация без ноутбука

В Android Chrome можно включить «Версия для ПК», распаковать ZIP через «Файлы» и добавить файлы через GitHub → Add file → Upload files. Внимание: нужно сохранить структуру подпапки icons. Если с Android это неудобно, создайте только пустой публичный репозиторий и передайте точное имя OWNER/REPO в чат с подключённым GitHub — после этого исходные файлы можно записать через API без ноутбука.

На GitHub не нужно хранить резервные копии, личные документы или заметки: сайт публичный. Прогресс не отправляется на GitHub.

## Обновления и безопасность данных

Обновляйте исходные файлы в том же репозитории — адрес сайта должен остаться неизменным. GitHub Pages публикует коммиты, PWA получает новые файлы при следующем открытии онлайн; иногда требуется повторный запуск. Версия офлайн-кэша меняется при сборке ZIP.

Не удаляйте данные приложения/Chrome и не переустанавливайте приложение без резервной копии. В «Ещё» доступен экспорт JSON; сохраняйте отдельную копию каждую пятницу.

## Уведомления

Таймер **не останавливается при закрытии карточки занятия**: сверху остаётся мини-панель, а время сохраняется локально с отметкой начала и восстанавливается после запуска. При возвращении PWA вычисляет прошедшее время по часам устройства. С разрешения Chrome возможны системные уведомления. После полного закрытия или принудительной выгрузки PWA Android не гарантирует своевременный фоновый сигнал. Для надёжного звука при закрытом приложении используйте стандартный таймер Android.

## Сборка

В каталоге проекта: python3 scripts/package-site.py
Для проверки: node --test tests/*.test.mjs

**GitHub Pages уже опубликован.** Не очищайте данные приложения при загрузке обновлений: прогресс и персональные страницы учебников сохраняются только в локальном хранилище планшета.

### Обязательное правило публикации новой версии

После изменения приложения выполните `python3 scripts/package-site.py` и обязательно отправьте в репозиторий вместе с кодом **новый `sw.js`**. Сборщик вычисляет идентификатор кэша по всем статическим ресурсам и фиксирует его в исходном service worker. Это необходимо, чтобы установленная PWA действительно запросила новую версию, а не оставалась на старом JavaScript. Контроль: `node --test tests/service-worker-cache.test.mjs`.

### Проверка после публикации

- `node scripts/verify-live.mjs` — обязательная проверка **всех 27 опубликованных ресурсов** по HTTP и SHA-256, с ограничением параллельности и повтором временных сетевых ошибок. При несовпадении или HTTP 404 завершится с ошибкой.
- `node scripts/verify-live.mjs --external` — дополнительная проверка сторонних страниц упражнений и ресурсов; она выполняется отдельно, поскольку доступность внешних сайтов не зависит от GitHub Pages.

Важно: временное `ERR` при HTTP-проверке — это сбой соединения проверяющего агента, не подтверждённый HTTP 404. Не очищать локальные данные планшета, чтобы исправить сетевую проверку.


## Почему планшет показывал старую версию (исправлено)

Ранее `sw.js` отдавал JavaScript и CSS из кэша без проверки новых файлов, а новая версия service worker ожидала закрытия открытых вкладок. Из-за этого HTML с GitHub Pages мог быть новым, но скрипты Android-PWA оставались старыми. Отдельный браузер на ноутбуке с чистым кэшем работал корректно.

Сейчас:

- сборщик `python3 scripts/package-site.py` присваивает уникальный идентификатор кэша по хешу ресурсов и записывает его в исходный `sw.js` для GitHub;
- установка service worker загружает все файлы с `cache: reload`, атомарно завершает предзагрузку и вызывает `skipWaiting()`; устаревшие кэши удаляются только после успешной установки;
- сам `index.html` содержит минимальный обработчик `controllerchange` и принудительную проверку новой версии, даже когда прежний `android.js` ещё находится в кэше;
- обновлённый `android.js` проверяет новые версии при запуске, возвращении на вкладку и восстановлении сети; в настройках есть кнопка **«Проверить обновления»**;
- при смене контроллера страница автоматически перезагружается один раз. `localStorage` и личные записи при этом не удаляются;
- без интернета остаётся последняя полностью установившаяся версия, переход к частично скачанному обновлению запрещён.

**Проверка на планшете:** подключите интернет, откройте **https://bochkov-anton.github.io/ege-2027/** в Chrome, затем закройте и вновь откройте приложение с иконки. В «Настройки → Установка на Android» нажмите «Проверить обновления» и проверьте отображаемую версию. Не очищайте хранилище и не переустанавливайте PWA: прогресс единственный и локальный.

Различные задания/отметки между ноутбуком и планшетом не связаны с версией: личные данные не синхронизируются между устройствами, их можно перенести только экспортом/импортом JSON.

Регрессионные тесты: `tests/service-worker-updates.test.mjs`, `tests/service-worker-cache.test.mjs`, `tests/android-pwa.test.mjs`.
