# Аудит учебных ссылок — ЕГЭ-2027 / октябрь 2026

## Причина изменения
Ранее приложение подставляло прямые PDF-адреса вида `doc.fipi.ru/.../2026/*.pdf` и отдельные ролики Rutube в карточки всех 234 тем. Некоторые PDF доступны при внешней проверке, но на Android PWA переход к ним мог открывать пустую страницу. При этом обобщённый PDF выдавался за точный материал к теме, а видеоссылки не имели подтверждённого отношения ко всем учебным действиям.

Новая политика: **прямые URL PDF/видео не используются в автоматически назначаемых источниках**. Ссылка ведёт на устойчивую главную страницу раздела ФИПИ или каталог соответствующего предмета, где обучающийся сам выбирает материал. На каждой карточке указывается название раздела и инструкция, рядом с ссылкой есть кнопка **«Скопировать адрес»** для запуска напрямую в Chrome, если встроенное окно пустое.

Это **подтверждение доступности страниц в проверяющем окружении**, а не гарантия отображения каждого внутреннего документа на каждом Android-устройстве. Ресурсы сторонних сайтов могут изменяться, попадать под блокировку сети, требовать JavaScript или иметь несовместимый встроенный просмотрщик.

## Требования к новым ссылкам

1. Прежде чем добавлять ссылку в базу приложения, проверить живой исходный сайт и конкретный URL, проверить тип ответа (HTML/PDF/видео), тематическую релевантность и год.
2. Если ресурс нельзя независимо проверить — не публиковать его как «официальный проверенный файл». Использовать родительскую доступную страницу с инструкцией.
3. Никогда не обещать, что пользовательская ссылка автоматически проверена; не загружать содержимое внешних ресурсов на сервер.
4. В мобильной PWA — **явно показывать URL**, «Открыть сайт» без обязательного `target=_blank`, «Скопировать адрес» и пояснение о внешнем интернете.
5. Периодически проводить выборочную ручную проверку ссылок на самом Android-планшете. Удалять подтверждённо недоступные ссылки; по возможности подбирать источник с той же педагогической задачей.
6. Не включать динамически сгенерированные прямые PDF, если их точное существование не подтверждено.

## Удалённые/заменённые классы адресов

- прямые PDF `https://doc.fipi.ru/navigator-podgotovki/navigator-ege/2026/...`: теперь вход через Навигатор ФИПИ;
- отдельные идентификаторы видео Rutube: убраны как неподтверждённые для точной темы;
- Math100 `/ege-profil2024/`: заменён на официальные варианты ФИПИ;
- каталог РЕШУ ЕГЭ — предпочтителен путь `/prob_catalog`, проверенный по трём предметам.

## Архитектурные проверки

`tests/resources.test.mjs`: проверяет, что для всех 234 тем URL находятся в явном allowlist доступных стартовых страниц, отсутствуют прямые PDF/видео, есть подсказки. `tests/ui-smoke.test.mjs`: проверяет отображение копируемого URL и кнопку копирования.

Идеально: будущий периодический link-checker в CI может делать HEAD/GET и сохранять дату/HTTP-результат, но по правилам браузерного CORS приложение само не может надёжно валидировать чужие URL. Сейчас **не заявляется**, что программно проверено каждое HTTP-обращение с планшета.
