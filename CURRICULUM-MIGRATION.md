# Перестройка плана без потери прогресса

## Задача

Старый план использовал дату недели и считал самостоятельные задачи допустимыми до освоения связанной теории. Ученик мог перейти к алкенам или сложным расчётам раньше необходимого фундамента.

Новая модель состоит из:
- **immutable topic ID**: `bio|chem|math:week:index`, сохраняются заметки, книжные записи, источники, результаты и ошибки;
- **dependency DAG**: `curriculum.js`, связей 363;
- **learning status**: `topicProgress[key]={theory,practice}`;
- **daily snapshot**: `curriculumAssignments[ISO-date]`, сохраняет реальные назначения дня;
- **legacy data**: `completed`, `reviews`, `timeSpent`, `assignments` и прочие старые поля без удаления.

## Совместимость

`C.migrateLegacy(state, L.planDay)` проверяет старые завершения по исходным идентификаторам блоков. Если теория и практика действительно отмечены, обе стадии считаются выполненными. Отметка одного блока подтверждает только теорию. Наличие неоконченного старого дня с фактической работой сохраняет старый маршрут этого дня: нельзя переприсвоить записанный результат другой теме.

Новое назначение на текущий день фиксируется один раз. Незавершённые этапы переходят на следующий учебный день через следующую доступную тему; прошлые задания не перезаписываются. Если старую задачу завершили уже после составления нового дня, дубликат этапа на сегодня скрывается, а исторический снимок сохраняется.

**Никогда не очищать** `localStorage`, хранилище PWA или архивные отметки автоматически. Сохранять пользовательский JSON до существенного обновления программы.

## Порядок и допуск

1. Прочитать теорию, Foxford/учебник, освоить нужные определения.
2. Отметить теоретический этап. Доступ к самостоятельной практике появляется только после этого.
3. Решить минимум три задачи и записать результат; не менее 80% требуется для зачёта практики.
4. По окончании практики назначить отсроченное повторение.
5. После освоения всех предпосылок открыть зависимую тему.

Если новая практика низкая по точности, доступна ранняя повторная проверка; она не засчитывается за освоение.

## ФИПИ-2027

Источник: https://fipi.ru/ege/demoversii-specifikacii-kodifikatory — пока **проект**. Финальный утверждённый КИМ перепроверять после публикации, в том числе номера и критерии. Ссылка на ФИПИ подтверждает требования экзамена, **не заменяет** учебную статью и задачи.

## Формальная проверка

```
node scripts/audit-curriculum.mjs
node scripts/audit-curriculum-complete.mjs
node --test tests/curriculum.test.mjs
node --test tests/fipi-crosswalk.test.mjs
node --test tests/ui-smoke.test.mjs
node --test tests/*.test.mjs
python3 scripts/package-site.py
```

Недостатки, требующие следующего этапа: атомарное разбиение многосоставных тем, ручная предметная ревизия каждой связи и каждой тематической подборки, дополнение неполной базы Foxford/учебников. Отчёт машинного аудита не равнозначен экспертной аттестации полноты всей подготовки.


### Дополнение v1.1: предварительные темы в интерфейсе

Модель учитывает 369 связей; если ученик открыл зависимую тему вручную, она показывает не только прямые требования, но и **транзитивную цепочку всех ещё не освоенных предпосылок**. Каждая строка открывает соответствующую тему, показывает прогресс теории/практики. Режим «пройти практику без освоения теории» не разрешён при зачёте. Точные данные старых дней, старые ID занятий и прогресс не удаляются. Подробная предметная ревизия — [CURRICULUM-AUDIT-2027.md](./CURRICULUM-AUDIT-2027.md).
