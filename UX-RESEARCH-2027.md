# UX research и дизайн-система ЕГЭ-2027 — второй проход

Дата: 2026-10-09. Приоритет: планшет 768–1199 CSS px, затем телефон и ноутбук.
Цель: уменьшить когнитивную нагрузку в ежедневном сценарии без потери глубины материалов и без манипулятивной «игровой» мотивации.

## 1. Исследованные первоисточники и применённые решения

| Источник | Подтверждённый вывод | Реализация |
| --- | --- | --- |
| Android Developers, [Adaptive navigation](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns) | Устройства средней ширины выигрывают от боковой navigation rail, компактные — от нижней навигации; экранную ширину, а не модель устройства, используют для адаптации | Сохранили 88px rail на планшете и шесть прямых разделов на телефоне, широкое рабочее поле |
| Google, [Build adaptive apps](https://codelabs.developers.google.com/jetpack-compose-adaptability) | Навигационная поверхность меняется с классом ширины | Одни и те же шесть логических разделов на разных ширинах, активный `aria-current` |
| Nielsen Norman Group, [Progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | Редко используемые команды и расширенный контент следует скрывать за доступным раскрытием, не смешивая с главным действием | Дневная нагрузка в `details`, дополнительные команды карточек через «Ещё», темы недели по предметам, чтение изданий в раскрываемом блоке |
| W3C, [WCAG 2.2 Target size Enhanced](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced) | 44×44 CSS px рекомендуются на уровне AAA для пользовательских сенсорных целей, отдельные исключения для ссылок в тексте | Основные элементы управления 44–48px, фокус виден, управляемое масштабирование не отключено |
| Carpenter, Pan, Butler, [Nature Reviews Psychology 2022](https://doi.org/10.1038/s44159-022-00089-1) | Интервальные повторы и извлечение из памяти поддерживают обучение | Повторение по памяти до самооценки, отдельная очередь повторений без добавления занятий на выходные |
| Agarwal et al., [Educational Psychology Review 2021](https://doi.org/10.1007/s10648-021-09595-9) | Retrieval practice в учебной среде имеет подтверждённую полезность | Вопрос-цель виден до чтения подсказок; оценка «Самостоятельно», «С подсказкой» или «Не получилось» |
| Duolingo, [Home screen learning path](https://blog.duolingo.com/new-duolingo-home-screen-design/) | Используется ясный следующий учебный шаг и понятный прогресс | «Следующее занятие» — главное действие дня; не перенимали ежедневные streaks и наказания за отдых |

### Ограничение переноса исследования

Эффекты retrieval practice доказаны для учебных стратегий в целом, но **не измерены** для конкретного ЕГЭ-планировщика. Использование похожего UI-паттерна не является экспериментальным доказательством роста баллов на экзамене. В проекте нет автоматической оценки правильности ответов; самооценка остаётся честно обозначенной.

## 2. Информационная архитектура

### Ключевой поток
`Сегодня → следующее доступное занятие → цель → короткая теория → самостоятельное задание → сохранение результата → повторение по памяти`.

Принципы:
1. **Один основной CTA**. На главном экране одна главная кнопка следующего занятия. Кнопки повтора и плана недели вторичные.
2. **Прогресс без давления**. Показ выполненных учебных блоков, а не «стрик». Пропуски не засчитываются как освоение. Суббота и воскресенье — отдых.
3. **Один источник истины**. Календарь, повторения, карточки и библиотека читают тот же учебный state и граф зависимостей.
4. **Материалы по необходимости**. Сначала короткое объяснение, потом ссылки и параграфы, затем практика. Дополнительные действия в «Ещё».
5. **Память перед подсказкой**. В повторении сначала раскрывается вопрос. Материалы можно открыть отдельно, но кнопки оценки сгруппированы внутри режима проверки.
6. **Проверяемая метрика**. Прогресс-бар имеет `aria-valuenow`, `aria-valuemax`, label. Дублирующий бар на том же экране убран.

## 3. Реализация по файлам

- `app.js`: `focus-board`, `daily-facts`, `day-mode`, `task-more`, `recall-check`, `week-course`.
- `tablet-ui.css`: таблица брейкпоинтов, адаптивная сетка главного экрана, достаточный размер кнопок, управление раскрытием, `focus-visible`, `prefers-reduced-motion`.
- `tests/ui-smoke.test.mjs`: проверка DOM-семантики, главного действия, последовательности повторения, сохранения состояния и расписания.
- `tests/tablet-ui.test.mjs`: публикация и структура адаптивных CSS.
- `scripts/package-site.py` и `sw.js`: обновление версии PWA, сохранение `ege2027-local-progress-v1`.

## 4. UX-аудит незакрытых рисков

- **Визуальное тестирование**. DOM-тесты подтверждают структуру, но не пересечения панелей и клавиатуры на физических устройствах. Нужно проверить реальные размеры 320, 375, 768, 820, 1024, 1194, 1366 CSS px, портрет/ландшафт, Android и iPadOS.
- **Контраст WCAG**. Целевой минимум — 4.5:1 для обычного текста, 3:1 для крупных надписей и контуров важных интерактивных объектов. Специального автоматизированного сканирования всего DOM на дату отчёта нет.
- **Сложные химические обозначения**. Обычные строки могут плохо передавать формулы экранному диктору; нужен последующий отдельный аудит семантики формул.
- **Проверка обучающего эффекта**. Нет пользовательского A/B-теста или данных о времени выполнения действий; интерфейс построен по доказательным принципам, но собственная количественная оценка улучшения пока отсутствует.
- **Реальная надёжность внешних материалов**. Отдельные URL и главы ещё требуют содержательной верификации. UI не объявляет их подтверждёнными без отдельной проверки.

## 5. План ручной проверки

1. На планшете открыть «Сегодня»: первая кнопка приводит к доступному уроку; 200% масштаб не обрезает действия.
2. Из меню «Ещё» открыть задания и пропустить занятие: действия в нужном контексте, предотвращение случайного пропуска остаётся.
3. Переключить нагрузку между `auto/160/90/35/отдых`, проверить дневной состав и сохранение; без занятий в выходные.
4. Открыть «Неделю»: химия и биология открыты, математика свернута; раскрытие показывает все 3 темы.
5. Повторения: сначала ответить по памяти, затем выбрать `Самостоятельно/С подсказкой/Не получилось`; дату следующего повторения не подменять алгоритмом интерфейса.
6. Проверить тему с глубокой зависимостью и длинными параграфами: возможность пройти от цели к практике и читать источники не теряется.
7. Проверить Android PWA старой версии после обновления и резервную копию: прогресс, заметки, ошибки, закладки сохранены.

## 6. Инварианты

234 темы, 369 зависимостей и ID не меняются. Прогресс хранится локально. UI не назначает дополнительные занятия и не изменяет правила повторения; только облегчает доступ. Выполнимость планирования 4–5 часов в день остаётся независимым требованием, проверяемым в тестах нагрузки. Продукт по-прежнему работает без удалённого бэкенда.
